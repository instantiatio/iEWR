# Компактные предметные aids DPF

[Путеводитель](GUIDE.md) помогает найти полезный DPF, [карточки](CARDS.md) —
применить несколько выбранных вкладов в обозначенных границах. Текущее правило
выбора и применения принадлежит [F](../../modules/formation/DOMAIN_WORK.md),
source bindings и глубина чтения — [S](../../modules/sources/GUIDANCE.md).
Это производные материалы iEWR, не новый DPF, owner или runtime route.

## Подготовка по потребности

1. Взять exact source и receiving use: быстро найти кандидата либо применить
   конкретный вклад. Проверить пригодность авторских оглавления, practical entries
   и справочника; переиспользовать достаточное. Не копировать все главы ради каталога.
2. Для ориентации записать source_id, edition, digest, вопросы, первый полезный
   результат, существенные границы и путь к авторской навигации. Весь repertoire
   остаётся доступным: короткая выборка не является полным каталогом применимости.
3. Карточку писать после чтения нужного pattern body, его условий и релевантных
   примеров/checks. Сохранить source meaning, шаги, входы, ограничения, first result,
   stop/reopen и точный source return. [Образец](CARD_TEMPLATE.md) — подсказка,
   не обязательная форма источника или отдельный файл на каждый паттерн.
4. Прямой сверкой с исходником проверить, что сжатие не добавило переход,
   полномочие, универсальность, причинный вывод или не потеряло условие. Назвать
   omitted uses, для которых нужен исходный раздел. Hash не проверяет смысл.
5. Перед заявлением выигрыша сравнить получение одного и того же результата
   с авторской навигацией и aid: правильный выбор/действие, сохранённые условия,
   source returns, чтение и общая нагрузка. Уменьшение размера не доказывает
   улучшения поведения. Если вместе с формой менялось содержание, различать вклады.

## Внешний DPF

При постоянном подключении действуют те же правила и
[границы регистрации](../../modules/sources/REGISTRATION.md). Существующую
достаточную проектную запись использовать повторно; стандартный производный locus
— `project/artifacts/dpf/GUIDE.md`, карточки при потребности — рядом. Не писать
производные материалы в source и не требовать от автора iEWR schema.

Одна overview-секция на exact source edition достаточна. Указать происхождение,
author status и ограничения; если сведения отсутствуют, отметить неизвестность.
Не достраивать признание/conformance из имени DPF. Регистрация без готовой
карточки остаётся пригодной для discovery; direct use не требует регистрации.
Не изменять package путеводитель ради project source. Оба набора доступны через S.

## Редакции и восстановление

Карточка/overview привязана к exact source_id + edition + SHA-256 (для directory
edition — объявленный inventory digest и exact member). Проверить actual source
перед первым reliance; достаточную проверку неизменных bytes переиспользовать.
Same edition с другими bytes — drift, а не разрешение переписать digest под тем
же смыслом. Новую revision явно обозначить; сравнить затронутые claims. Старую
карточку, если она была основанием решения, сохранить по действующим правилам
проекта. Stale aid исключается только из dependent use; source можно читать напрямую.
Снятие регистрации не удаляет исходник, прежний aid или историю использования.

Присутствие карточки не меняет статус метода, не создаёт formal Work claim и не
разрешает исполнение source commands или транзитивное чтение FPF. Отдельные DPF
могут предлагать incompatible или unresolved claims: сохранить их точный смысл
и вернуть спорный вклад его владельцу, не объединять механически.
