# Структурный индекс FPF

`navigation/fpf-index.yaml` — автоматически полученная структура точного оригинала `external-sources/fpf/FPF-Spec.md`. Пути разрешаются от корня установленного проекта. Редакция, происхождение и SHA-256 указаны в индексе и сверяются с `external-sources/fpf/SOURCE.json`.

## Состав

- `source` — путь оригинала, repository/commit, заявленная версия, байты, SHA-256 и путь/хеш SOURCE.json.
- `sections` — все ATX-заголовки Markdown вне fenced code и HTML-комментариев, в исходном порядке. Для каждого сохранены исходное название, уровень, родитель, ID из заголовка, если он явно распознаётся, и расположение полного раздела. Списки и таблицы внутри раздела доступны в его полном тексте; они не превращаются в новые разделы.
- `location.start_line/end_line` — строки оригинала, от 1, обе границы включены. Диапазон включает подразделы и заканчивается перед следующим заголовком того же или более высокого уровня. Он действителен только при совпадении SHA-256 оригинала.
- `key` — адрес строки внутри этой точной редакции. Это технический ключ, не придуманный FPF ID. У ненумерованного заголовка `id: null`; исходное название сохраняется.
- `declared_type` и `declared_status` — только явно записанные значения, со строкой и местом объявления. Объявления в тексте раздела и оглавлении сохраняются отдельно, включая различия; тип/статус не наследуются от родителя. Пустой список означает отсутствие извлечённого объявления.
- `toc_entries_without_body` — пункты оглавления, для которых нет заголовка полного раздела. `location: null` показывает отсутствие адреса полного текста; заявленный статус, например Planned, сохраняется.
- `unmatched_toc_metadata` — явные строки метаданных оглавления, которые не удалось разобрать. При непустом списке проверь их по указанным строкам; индекс не достраивает результат.

Пункт оглавления не доказывает наличие полного метода. Название, тип и статус не заменяют чтение оригинала. Индекс не пересказывает условия/зависимости и не содержит рекомендаций выбора или локальных процедур. Входы по задачам и MethodPack ведутся отдельно.

## Получение и проверка

Из корня установленного проекта:

```sh
python3 -B tools/build_fpf_index.py
python3 -B tools/build_fpf_index.py --check
```

Генератор работает на стандартной библиотеке Python. Чужой рабочий каталог задаётся через `--root /absolute/project/path`. `--check` ничего не пишет: повторно получает структуру и сверяет весь индекс с текущим точным источником. Несовпадение оригинала с SOURCE.json останавливает обе команды. Автоматической загрузки или переключения FPF нет.

При смене редакции сначала сохрани используемые прежние оригинал, происхождение и индекс; получи разрешённую новую редакцию с её SOURCE.json и пересоздай индекс. Проверка обнаружит устаревшую структуру. Сам индекс не переключает прежние применения и не проверяет смысл изменений метода.

## Чтение по адресу

Найди нужную запись по исходному ID или словам названия. Проверь SHA-256/редакцию, открой указанный диапазон строк **оригинала**, прочитай существенные условия и нужные адресные зависимости. Для структурного пункта вроде `C.43:4.2` при необходимости открой также родительский метод `C.43`. Метаданные оглавления служат сведениями источника, не отдельным заключением о пригодности.

Пример обычных средств ADE:

```sh
rg -n 'id: "C.43:4.2"' navigation/fpf-index.yaml
sed -n '89668,89677p' external-sources/fpf/FPF-Spec.md
```

Числа в примере относятся к поставленной редакции `c3b34de07a6bd2df85c7081a4c367fd09978079c`; для иной редакции возьми диапазон из её индекса.
