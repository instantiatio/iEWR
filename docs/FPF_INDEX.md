# Структурный индекс FPF

`navigation/fpf-index.yaml` — автоматически полученная структура точного оригинала `external-sources/fpf/FPF-Spec.md`. Пути разрешаются от корня установленного проекта. Редакция, происхождение и SHA-256 указаны в индексе и сверяются с `external-sources/fpf/SOURCE.json`.

## Состав

- `source` — путь оригинала, repository/commit, заявленная версия, байты, SHA-256 и путь/хеш SOURCE.json.
- `sections` — все ATX-заголовки Markdown вне fenced code и HTML-комментариев, в исходном порядке. Для каждого сохранены исходное название, уровень, родитель, ID из заголовка, если он явно распознаётся, и расположение полного раздела. Списки и таблицы внутри раздела доступны в его полном тексте; они не превращаются в новые разделы.
- `location.start_line/end_line` — строки оригинала, от 1, обе границы включены. Диапазон включает подразделы и заканчивается перед следующим заголовком того же или более высокого уровня. Он действителен только при совпадении SHA-256 оригинала.
- `key` — адрес строки внутри этой точной редакции. Это технический ключ, не придуманный FPF ID. У ненумерованного заголовка `id: null`; исходное название сохраняется.
- `declared_type` и `declared_status` — только явно записанные значения, со строкой и местом объявления. Объявления в тексте раздела и оглавлении сохраняются отдельно, включая различия; тип/статус не наследуются от родителя. Пустой список означает отсутствие извлечённого объявления.
- `toc_entries_without_body` — пункты оглавления, для которых нет заголовка полного раздела. `location: null` показывает отсутствие адреса полного текста; заявленный статус, например Planned, сохраняется.
- `unmatched_toc_metadata` — явные строки метаданных оглавления, которые не удалось разобрать. При непустом списке проверь их по указанным строкам; индекс не достраивает результат.

Пункт оглавления не доказывает наличие полного метода. Название, тип и статус не заменяют чтение оригинала. Индекс не пересказывает условия/зависимости и не содержит рекомендаций выбора или локальных процедур. Входы по задачам и MethodPack ведутся отдельно.

## Обновление FPF готовой парой

Для текущей работы используется уже поставленная точная пара. Её чтение и применение не требуют запуска генератора или обязательного Python. Смена редакции FPF относится к обслуживанию методологической основы и выполняется по прямому поручению; новая ссылка или появившийся файл сами не переключают действующую основу.

Основной путь обновления — получить **готовую согласованную пару оригинала FPF и структурного индекса**. Вместе с ней нужны точная редакция и происхождение (`SOURCE.json`), сохранённые лицензии/условия и достаточное основание проверки именно этой пары. Это могут быть опись и результат проверки подготовившего комплект поставщика с точными байтами/хешами и областью проверки; одно название поставщика или утверждение «индекс готов» недостаточно. Формат и пути должны быть совместимы с установленным iEWR. Нового обязательного файла или реестра для этого не вводится.

1. Сохрани прежние использованные оригинал, индекс, происхождение и необходимые основания либо проверь их точную доступность. Новую пару подготовь отдельно от действующей; оригинальный авторский текст не редактируй.
2. Доступными средствами ADE сверь фактические bytes/SHA-256 оригинала, SOURCE.json и индекса с точной описью полученного комплекта. Проверь указанную в индексе редакцию, source hash, привязку к SOURCE.json, формат и пути. Установи достаточное основание правильности структуры для этих исходных байтов. Совпадающий source hash в шапке сам не доказывает правильность всех записей/диапазонов. При неизвестном основании, несовместимости или расхождении удержи подключение новой пары; старая пригодная пара остаётся доступной.
3. По IE-M004 и A.10.1 проверь действительно зависимые адреса, закреплённые SHA/редакции и условия использования в навигации, MP и метаданных среды. Исправь затронутое в порученных пределах и выполни достаточные проверки. Старые применения остаются при своих основаниях; новая редакция не переписывает их молча.
4. Подключи проверенный комплект только в разрешённой области и при согласованных условиях записи/чтения. Перечитай результат, сверь фактическую согласованность оригинала/происхождения/индекса и зависимых текущих входов. Переключение нескольких файлов само не является атомарной транзакцией. При прерывании сначала выясни фактическое состояние; не выдавай смешанные редакции за готовую пару. Операции среды выполняются по IE-M004, отдельный пользовательский режим не нужен.

Если готовая пара и основания достаточны, **локальная генерация не требуется**. Наличие только нового оригинала без согласованного индекса не завершает обновление. Отсутствие нужных возможностей ADE удерживает зависимую смену основы, а не всю независимую работу по прежней паре.

## Локальная подготовка и проверка при доступном Python

Поставленный генератор — готовый инструмент подготовки/обслуживания комплекта. Для него нужен Python; альтернативный генератор этой поставкой не реализован. Его наличие не делает Python обязательным для работы iEWR или обновления MP.

Из корня установленного проекта:

```sh
python3 -B tools/build_fpf_index.py
python3 -B tools/build_fpf_index.py --check
```

Генератор работает на стандартной библиотеке Python. Чужой рабочий каталог задаётся через `--root /absolute/project/path`. `--check` ничего не пишет: повторно получает структуру и сверяет весь индекс с текущим точным источником. Несовпадение оригинала с SOURCE.json останавливает обе команды. Автоматической загрузки или переключения FPF нет.

При доступном подходящем Python используй готовый `--check` для нужной проверки полученной пары. Это проверка без записи; не подменяй полученный индекс молчаливой перегенерацией. Локальная генерация выполняется при порученной подготовке/обслуживании после сохранения прежней основы. Генерация и проверка структуры не устанавливают смысловую пригодность новой редакции или отсутствие влияния на прежние результаты.

## Чтение по адресу

Найди нужную запись по исходному ID или словам названия. Проверь SHA-256/редакцию, открой указанный диапазон строк **оригинала**, прочитай существенные условия и нужные адресные зависимости. Для структурного пункта вроде `C.43:4.2` при необходимости открой также родительский метод `C.43`. Метаданные оглавления служат сведениями источника, не отдельным заключением о пригодности.

Пример обычных средств ADE:

```sh
rg -n 'id: "C.43:4.2"' navigation/fpf-index.yaml
sed -n '89668,89677p' external-sources/fpf/FPF-Spec.md
```

Числа в примере относятся к поставленной редакции `c3b34de07a6bd2df85c7081a4c367fd09978079c`; для иной редакции возьми диапазон из её индекса.
