# Правила README и release notes iEWR

README помогает пользователю понять назначение iEWR и начать работу. Release notes объясняют, что изменилось и что нужно сделать при обновлении. Пиши для человека, который пользуется средой; каждую подробность связывай с его вопросом, выбором или действием.

## README

Начни с назначения и пользы среды. Дай короткий порядок начала работы и при необходимости один понятный пример задачи. Покажи, где размещать материалы и искать результаты. Объясняй DPF и другие необходимые термины при первом употреблении.

Указывай условия, влияющие на начало работы: нужные возможности агентской среды, статус версии и существенные ограничения совместимости. К подробным руководствам направляй ссылкой, когда они нужны для отдельного действия.

## Release notes

Укажи версию и её фактический статус. Для каждого существенного изменения объясни, что теперь доступно пользователю, изменилось в его работе или требует его действия. Сохрани важные условия обновления, известные ограничения и ссылку на миграцию, если они относятся к этой версии.

Не выдавай подготовленную версию за опубликованную. Описывай только вошедшие изменения; предложения, планы и результаты проверок отличай от возможностей продукта.

## Отбор и редактура

Применяй WEP из текущего репертуара: выбери достаточную редактуру по WEP.1, сохраняй существенные отношения по WEP.2, организуй содержание по WEP.5 и проверь результат по WEP.12. Для нового текста используй WEP.4; термины, защищённые строки и ссылки сверяй по WEP.9. Прочитай нужные разделы метода; перечень кодов не заменяет применения.

Убирай технические сведения, если без них пользователь может так же понять продукт и выполнить нужное действие. Хеши, внутренние идентификаторы, схемы, устройство модулей, история разработки и протоколы проверок обычно остаются в технических документах. Сохраняй конкретную техническую деталь, если она нужна для установки, совместимости, использования или устранения проблемы. Существенное условие не прячь за ссылкой.

Пиши прямо и естественно. Убирай дубли, необъяснённые сокращения, служебные оговорки и неподтверждённые обещания. Объём определяй задачей читателя; обязательной длины и неизменного шаблона разделов нет.

## Проверка перед завершением

Сопоставь текст с фактическими изменениями и исходными материалами. Затем прочитай его отдельно: понятны ли назначение, ближайшее действие и существенные условия? Проверь версию, статус, совместимость, точные строки атрибуции и адреса ссылок. Проверку написанного адреса отличай от фактического открытия страницы. Исправь найденные помехи и заверши, когда текст выполняет свою задачу.
