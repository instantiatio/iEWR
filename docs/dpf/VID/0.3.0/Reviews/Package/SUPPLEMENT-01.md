## F5 — точность смысла No116

Независимо прочитанный в exact snapshot S24 CSV row No116 говорит: `A badge chip or pill label should stay whole on one line when practical and disclose unavoidable truncation`. Это **однострочность текста внутри отдельной компактной метки при практической возможности**, с раскрытием полного значения, а не один элемент коллекции на ряд. No115 отдельно разрешает wrap всей коллекции.

VID.4:11 в нынешнем candidate пересказывает это как «Требование No116 всегда держать одну плашку в строке». Фраза теряет условие *when practical* и может назначить правило геометрии коллекции вместо текста метки. В source→candidate row первого ASSESSMENT была верно поддержана сама доступная адаптация, но недостаточно отделена от этой неточной исходной атрибуции. Таким образом, **disposition source carry-through для точного пересказа No116 — incorporated with an unaccepted meaning shift**, пока фраза не исправлена.

Минимально уточнить исходное условное nowrap внутри одной метки и явно сохранить принятое разрешение переносить обязательный длинный текст/менять форму ради полной доступности. Новая универсальная однострочность, отмена reflow или дополнительный Human gate не нужны. Source/currentness и content adequacy различаются: правильный commit S24 не делает этот пересказ правильным. Остальные conclusions P1 semantics/No115/117/118 сохраняют свои основания.

## F6 — расположение новых условных действий относительно остановки

В изменённых Solution .1:4/.9:4/.4:4/.10:4/.5:4/.6:4 ранее существовавшая фраза «Остановитесь/Закончите» предшествует добавленному последнему абзацу. Например, в .9 после «Закончите при сохранённой работе изображения» ещё нужно распознать функцию компактного знака; в .5 после «Остановитесь…» помещена late-resource ветвь.

Полное чтение позволяет восстановить условное действие, поэтому это не установленная потеря метода. Но текст может преждевременно сигнализировать завершение до новой необходимой проверки. Минимальный content-preserving repair — поместить общий stop после применимых conditional ветвей либо сделать его явно относящимся лишь к уже завершённой подзадаче. Это не основание требовать все ветви для каждой страницы. После ремонта повторно прочитать positive path и stop, сохраняя локальную достаточность/независимое продолжение.
