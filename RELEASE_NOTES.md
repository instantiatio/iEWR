# Изменения iEWR 5.5.4 Beta

Усилено восстановление после возвращения к работе (E-min). Перед содержательным
продолжением должны быть связаны текущие основания управления, точные редакции
используемых материалов и фактические действия/последствия. Неоднозначный выбор
инициативы, неполные сведения или неизвестный эффект удерживают продолжение с
конкретным пробелом. Завершённая инициатива не порождает новое действие.

Добавлены переносимый помощник восстановления, который только читает сведения,
и отдельный [DSH consumer](adapters/dsh-reentry/README.md). Работа по `AGENTS.md`
в Codex и других средах сохраняется без этого адаптера. Для технического контроля
в DSH требуется отдельно подключить и проверить программный bootstrap; наличие
файлов в ZIP его не активирует. Прежние recovery API сохранены, но несвязанные
accounts, неизвестная полнота и выбор без прямого основания теперь дают hold.
Исторические записи автоматически не мигрируются; для их использования могут
потребоваться точные ссылки и недостающие основания.

Функциональный код соответствует проверенной доработке E-min: 38 Python и
16 Node regression tests, включая настоящий вызов Python из consumer. Состав,
контрольные суммы, граф зависимостей и чистая распакованная поставка проверяются
отдельно; точный протокол сопровождает ZIP вне продукта. Core Contract, DPF и
границы полномочий сохранены. Проверки локальны: поведение модели, действующий
DSH loader и доверие к его каналам, работа других host и upstream TypeScript
type-check остаются неподтверждёнными. [iEWR 5.5.4 Beta](https://github.com/instantiatio/iEWR/releases/tag/5.5.4-beta)
опубликован как Latest по прямому поручению пользователя. Точный ZIP и тег
сохранены без изменений; main отражает факт публикации и не расширяет пределы
проверок. Прежние изменения сохранены в [истории](RELEASE_HISTORY.md).
