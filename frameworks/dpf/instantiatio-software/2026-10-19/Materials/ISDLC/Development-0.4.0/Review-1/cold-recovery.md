# Холодное восстановление, reviewer 1

Объект: ISDLC 0.4.0, sha256 1950a2409950ec04211f32a6ef37daea55db7dba034a6699698573ceffae3d6a. Зафиксировано до чтения SOURCES, Decision, прежних оценок и новых Applications. Основа: только публикация DPFs/ISDLC.md, её Readme, Reference, методы 1–9 и C1–C6. Не является наблюдением human/production use.

Из вопроса о правке optional параметра выбираю CODE → .15/.16/.11; достаточно сохранить старый вызов и различить новый параметр. БД, UI, DDB и SVV не обязательны. Из вопроса о потерянном ответе выбираю RETRY → .5/.4/.7 и .6 для представления. Сначала устанавливаю фактическую границу эффекта и подтверждения; один HTTP 200 не завершает прикладную операцию. Сохраняю principal/key/payload до получения пригодного результата; конкурентный дубль отличается от нового запроса.

Для C6 из публикации восстанавливается следующий конкретный ход: требование — ровно q либо отказ; сохраняемый факт содержит qty и цену покупки, 3×199=597 при изменении текущего каталога до 250. Механизм должен согласованно зафиксировать условное уменьшение, резерв и результат операции; иначе внешняя гарантия не получена. При недостатке базовой .4/.5 выбираю DDB.1/.2/.3/.5 для конкретного пробела, не весь lifecycle. Oracle по .11 — полный комплект и сохранение суммарного ресурса, а не непустой ответ; случаи 0,1,C,C+1, повтор одной операции, новая операция и сбой после commit. SVV.1/.2/.4 требуется лишь при недостаточности общего построения проверки. Unknown клиента не становится success и не разрешает новый key для того же намерения.

Для изменения 199→1990 сохраняется смысл цены, но 1995 не представимо старым целочисленным reader; .12 требует ограничить mixed-domain либо выбрать другой согласованный переход. Snapshot до B не содержит B: .13 требует проверенной дельты либо принятой допустимой потери; факт запускаБД недостаточен. Изменение единицы/writers переоткрывает зависимые checks (.11/SVV.6), спор о комплекте возвращает к.1, ошибка механизма к.4/DDB, ошибка подтверждения к.5/.7.

По одним текстовым примерам не получены реализация, фактическая конфигурация, выполненные tests, допустимая потеря данных, конкретный атомарный механизм и решение о выпуске. Остановка аналитического восстановления — получены предметные действия, конкретные неизвестные и адреса возврата. Непонятного обязательного скрытого DPF-маршрута из публикации не обнаружено.
