# Instantiatio SDLC DPF

Предметный методологический фреймворк жизненного цикла программного обеспечения.

**Редакция 0.1.0, 6 октября 2026. Авторский кандидат для ограниченной проектной пробы.**

Фреймворк помогает разработчику, архитектору, техническому руководителю и помогающему AI выбрать достаточный инженерный способ: определить нужный результат, согласовать проектирование, изменить реализацию, проверить свойства, поставить и сопровождать продукт. Практический акцент — web, mobile, backend и реляционные данные.

Начните с вопроса в [основном описании](DPF.md#entry), затем откройте соответствующий полный паттерн. Для нормализации данных используйте ISDLC.4, для UI/UX и дизайн-систем — ISDLC.6, для API — ISDLC.5. Вопрос «что менять вместе?» ведёт к ISDLC.10; вопрос «почему ошибка?» — к существующему внешнему SDLC.3 по указанному в описании пути.

Методы выбираются по текущему вопросу; порядок разделов не задаёт процесс исполнения. Фреймворк не предоставляет полномочий менять систему, выпускать продукт или управлять агентной средой. Подключение к iEWR, формальное принятие и публикация — отдельные действия.

Эта редакция содержит предлагаемые способы и сконструированные случаи. Она не объявлена Stable, не имеет независимого полного результата E.21 и не прошла испытание на реальном проекте. Указанные проверки позволяют передать различимый авторский кандидат для первой ограниченной пробы, а не утверждать промышленную пригодность.

Файлы этой передачи сохраняются совместно. После передачи существенное исправление оформляется следующей редакцией; 0.1.0 сохраняет свои основания и результаты проверки. Идентификаторы ISDLC — локальные адреса предлагаемой серии; они не переименовывают существующие SDLC.1–SDLC.4.
