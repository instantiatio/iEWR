# Проверка Instantiatio SDLC DPF 0.2.1

## Предмет и вывод

Проверяемый результат — авторская локальная доработка по R1/R2 и U1/U2 независимого ревью 0.2.0. Основание — прямое поручение Human и распределение в [FORMATION.md](FORMATION.md). Дата проверки — 2026-10-06. Оценка относится к exact новой редакции; прежний отчёт Astra не объявляется независимым review новых bytes.

**Вывод:** предусмотренные четыре изменения внесены и повторно проверены в авторском scope. Внутренний способ выбора структуры/алгоритма дополнен; источники и проверки декомпозиции разделены; конкурентный повтор и объявление UI-статуса уточнены. Число паттернов и предметные границы сохранены. Комплект можно передать для ограниченной проектной пробы; реальная полезность читателю, полный E.21 и PackageAdequacyStatus этой проверкой не установлены.

## Замечание → исправление → повторная проверка

| Замечание | Изменение | Проверка того же требования и предел |
|---|---|---|
| R1/P2 | Практический вход, ISDLC.3:1–5/7/11; карта | Текст даёт операции/семантику, выбор представления, сохранение результата, стоимость/память и границу оценки. Конкретный импорт различает быстрый неправильный выход и корректную альтернативу. Не объявлен полный курс алгоритмов |
| R2/P2 | ISDLC.4:4/5/7/11; S08/S27 | Отдельно объяснены binary lossless criterion и контроль зависимостей; Product/OrderLine обоснован, AB/BC даёт контрпример. Роль S08 сужена; более сильные положения имеют точный S27. SQL/runtime conformance не испытаны |
| U1/P3 | ISDLC.5:4/5/7; C1 | Два одновременно пришедших principal/key/payload относятся к одной операции; результат либо объявленный pending различают самоповтор и независимый slot conflict. Пример — контракт, а не выполненная concurrent implementation |
| U2/P3 | ISDLC.6:4/5/7/11; C1 | Status message программно объявляется без обязательного получения фокуса; обоснованное движение фокуса и keyboard path проверяются отдельно. Реальный UI/assistive technology не запускались |

R1/R2 не закрыты одним добавлением библиографии: изменены действия, пример, checklist и источник сравнения. U3 о сравнительных формулировках остаётся необязательным улучшением; его устранение не приписано этой редакции. Независимое подтверждение исправлений Astra сейчас не получено.

## Конструктивные проверки примеров

Для двух математических примеров выполнено вычисление отдельным авторским Python-скриптом. Он не извлечён из frozen источников и не исполняет приложение, SQL или pipeline. Числовые наблюдения относятся только к указанным входам; общие границы аргументированы содержанием и выбранными источниками.

| Проверка | Вход / наблюдение | Значение и предел |
|---|---|---|
| Первые записи и порядок | `(b, firstB), (a, firstA), (b, nextB), (c, firstC)`; последовательный поиск и список с membership-set дали `b/firstB, a/firstA, c/firstC` | Предложенные представления сохраняют контракт на этом входе; инвариант префикса объяснён в тексте |
| Неправильное ускорение | Сортировка результата по ключу и сохранение последнего значения дали другие результаты | Быстродействие не закрывает потерю семантики; конкретные неправильные варианты различены |
| Цена последовательного поиска | 100 различных ключей: сумма 0…99 равна 4950 сравнениям | Проверена указанная квадратичная сумма; runtime benchmark hashing не проводился |
| Product/OrderLine | Три текущих факта о двух продуктах и двух заказах спроецированы и соединены; JOIN совпал с исходными фактами | Дополнительно по FD product_id определяет Product, пара order/product — qty; SQL PK/FK/NOT NULL названы как проектные условия, не исполнялись |
| Различие dependency/lossless | `(1,x,red), (2,x,blue)` → AB и BC → четыре строки, включая `(1,x,blue)` и `(2,x,red)` | Сохранённая A → B не устраняет ложные сочетания. Общий B не определяет ни AB, ни BC по данной FD |
| Одновременный дубль | Аналитически рассмотрены pending первой операции, второй запрос и завершение | Согласованный результат/pending имеет путь чтения; самоконфликт или новый эффект — различающий неправильный вариант. Race detector/runtime evidence отсутствуют |
| UI-статус | Аналитически рассмотрены waiting/conflict/unknown и сохранение клавиатурного пути | Статус и focus decision имеют разные проверки; нет заявления о соответствии несуществующего интерфейса WCAG |

Условия hashing — стоимость ключа, распределение/коллизии, память и expected/amortized reach — сохранены. Для нормализации различаются реляционная FD-модель, конкретные SQL constraints и исторический факт цены. Успех этих маленьких вычислений не доказывает перенос на любые inputs, СУБД или языки.

## Дальнейшее использование

Полезная реальная проба должна проверить вклад исправленных действий: объяснение выбора представления, декомпозиции, concurrent retry и интерфейсного статуса без дополнительного неописанного способа. ## Финальная техническая сверка
