## Предлагаемое изменение состава

В предметной роли общего software-development базиса предлагается использовать объединённый ISDLC вместо прежнего отдельного SDLC DPF. Четыре code methods уже включены полными телами; одновременное объявление старого SDLC необходимым базовым методом создаст лишний lookup и дублирование. Прежний отдельный SDLC сохранить как provenance и основание прежних ссылок; не изменять её bytes или значение SDLC.1–4.

| Прежний адрес | Полезный внутренний адрес в новом фреймворке | Условие перехода |
|---|---|---|
| SDLC.1 | ISDLC.15 | Адаптация понимания кода; старый адрес остаётся адресом прежней публикации |
| SDLC.2 | ISDLC.16 | Конкретная правка кода; product slice отдельно в ISDLC.10 |
| SDLC.3 | ISDLC.17 | Диагностика; восстановление сервиса отдельно в ISDLC.13 |
| SDLC.4 | ISDLC.18 | Рефакторинг; решение о ремонте отдельно в ISDLC.14 |
| ISDLC.1–14 редакции 0.1.0 | Те же ISDLC.1–14 редакции 0.2.2 | Продолжение решений с обновлёнными внутренними связями |

Это карта содержательного соответствия, а не alias redirect в runtime или утверждение тождества редакций. Historical references продолжают разрешаться к своим exact sources. Новый читатель выбирает метод по практическому вопросу, а не по имени DPF или обязательному lifecycle.

## Работа в будущем порученном baseline

Действующее руководство — [указатель Bundled DPF Baseline Refresh and Integration Guide](SOURCE_LOCATORS.md#baseline-guide). Оригинал руководства следует использовать из конкретного целевого baseline. Он требует отдельного scope baseline maintenance и различает доступность источника, его вклад, выполнение и принятие. Для фактической интеграции в будущем:

1. Установить конкретный исходный baseline, прямое поручение на его изменение и принятый состав. Сохранить исходный пакет и inventory; не считать эту заметку blanket permission.
2. Проверить exact 0.2.2 по MANIFEST.sha256, status и source tuple. Разместить новую edition в выбранном source locus без перезаписи прежних экземпляров. Нужные provenance files/locators и условия распространения согласовать для этого carrier.
3. Обновить соответствующие product catalogue, publication locator, entry links, repertoire и package inventory по действующим contracts. Согласовать source identity, title, edition и digest; каталог этой проектной передачи сам по себе не является registration или product path.
4. В новом месте проверить все relative file/fragment links. Пути к FPF/ME/SYSE/старому SDLC служат точным основаниям; при ином carrier их нужно разрешить или явно заменить устойчивыми locators без потери identity. Не делать автоматическую загрузку/полное чтение FPF условием ordinary method use.
5. Проверить affected S/F uses: обнаружение метода по вопросу, вклад нового внутреннего тела, отсутствие обязательного lookup в старый SDLC, соответствие покрытия и stops. Подойдут реальные bounded случаи изменения API/caller, диагностики и refactoring с конкретными наблюдениями. Discovery без подсказки и применение supplied Method дают разные evidence; не смешивать их.
6. Провести нужные regression/package checks, зафиксировать failures/skips и exact новый package tuple. Источник остаётся bounded source для существующих owners; новых runtime routes, Core types, workflow engine или полномочий он не создаёт.

Сейчас эти действия не выполнялись. Ни один будущий путь, registration ID, release number или результат интеграционной пробы не выдуман. Следующий maintainer продолжает от фактического scope, а не от предположения, что наличие Markdown уже подтверждает baseline quality.

## Пределы готового материала

Передан объединённый authored candidate с полными телами и проверенными локальными ссылками. Нет независимого reader trial, полного E.21 для новой серии или formal PackageAdequacyStatus. Если будущая поставка заявляет более сильную пригодность, нужны соответствующие основания и проверки под её exact receiving use; запись в комплекте не повышает maturity автоматически.

Это не препятствует подготовке будущего решения о составе: содержание и известные пределы уже различимы. Для текущего поручения обязательного следующего действия Human нет; сама установка выполняется в выбранном будущем обновлении.

## Дельта после ревью

Выбранный кандидат 0.2.2 продолжает исправления R1/R2 и уточнения U1/U2 редакции 0.2.1 по ревью 0.2.0; дополнительно различены отсутствие аргумента и несуществующее значение edition в ISDLC.16:5 по полному ревью 0.2.1. При включении проверять уже эти exact bytes: старое ревью не является независимым результатом для новой редакции. Состав остаётся 18 паттернов; текущий iEWR не изменён. Следующая meaningful проба должна различить сохранение порядка и первых записей при выборе структуры, корректность декомпозиции, concurrent duplicate одной операции и доступное объявление статуса.

В переносимом архиве текущие source links ведут к SOURCE_LOCATORS.md; прежние редакции и отчёты сохранены побайтно, включая их исторические workspace paths. Импорт в project/source/ целевого проекта делает комплект входным материалом. Фактическое включение в продукт выполняется по отдельному поручению; архив не является установщиком.
