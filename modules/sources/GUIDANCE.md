# S — semantic/domain sources

S владеет exact bindings, contribution и claim comparison; не исполняет source,
не решает Method/permission/authority, не выбирает namespace как route. FPF Core
владеет semantic distinctions. Applicable DPF/LPF — external bounded domain
contributions; organization/project policy и Human decisions имеют собственных
direct owners. Каталог, directory order, label или дата не задают precedence.
Material conflict возвращается exact claim owner.

Входящие материалы сохранять по [общему порядку файлов](../../project/README.md):
оригинал не перезаписывается преобразованием или новой входящей редакцией;
существенные происхождение и связь с известным предшественником сохраняются.
Нужная прежняя source basis остаётся доступной; latest не заменяет её историю.
Исключение требует прямого разрешения на затронутое действие, не вывода из каталога.

Read-only `inspect_binding`, `SourceResolution.inspect/candidates/verify/contribute`
дают bytes/identity/loci/limits. RepertoireReader ограничен DPF repertoire roots;
произвольные direct DPF/LPF bindings читаются отдельным bound SourceReader.
Package/project availability рассматриваются вместе без semantic приоритета.
Ни lookup, ни required package slots не applicability/conformance.
Required slots — maintainer profile в tools/package, не S runtime algorithm.

## Самостоятельное обнаружение и достаточное чтение

При выборе основы по F использовать вместе `frameworks/dpf/REPERTOIRE.yaml`
и существующий `project/dpf/REPERTOIRE.yaml`. Неизвестные entries проверять по
содержанию наравне с известными; отсутствие project index не создаёт его.
Для быстрого выбора есть [единый указатель](../../catalog/dpf/METHODS.md) и,
если подготовлен, один проектный указатель project/artifacts/dpf/GUIDE.md либо
существующий пригодный файл. Навигация не заменяет состав репертуара:
неизвестный entry проверяется по источнику наравне с остальными. Указанный
пользователем exact source можно читать напрямую без регистрации.

Начать с вопроса и первого нужного результата. Указатель и авторское оглавление
помогают найти метод; применимость устанавливается по его нужному original body:
действия, условия, ограничения, first result/stop и decision-bearing зависимости.
Для спорного вывода, примера или недостающего условия читать соответствующий
исходный раздел. Наличие ссылки, названия или краткого описания не заменяет
содержательного применения. Разделы читаются по месту; полное чтение DPF
не является обязательным способом доступа.

Оглавление использовать для адреса нужного раздела; сначала читать этот диапазон,
а не возвращать все заголовки и упоминания всего файла. Расширять чтение лишь
для недостающего условия или зависимости. Уже прочитанные инструкции доступа
и регистрации переиспользовать в том же неизменном контексте; не перечитывать
их целиком перед каждой проверкой или записью. Это не отменяет проверки
текущих файлов перед изменением и сверки фактического результата после него.

Перед первым reliance сверить source identity/edition/digest с actual source
и текущим binding. При проверенной неизменной основе повторное чтение/hash
не нужны. Changed/missing binding удерживает зависимый use до проверки;
same edition с другими bytes — drift, а не разрешение заменить digest.
Новую редакцию связывать явно, проверить навигацию и изменившиеся условия,
затрагивающие текущий результат. Прежние источники и uses не переключаются
на latest молча.

Чтение и применение DPF не запускают создание карточек, копий глав или
дополнительного справочника. Прочитанная достаточная основа переиспользуется;
сохранять нужные основания текущего результата по общим правилам проекта.
S.read остаётся read-only. Ни один из этих входов не требует полного чтения
всех DPF или FPF-Spec.

Registration нужна только для persistent discovery: in-place inspect/hash,
explicit metadata/edition и project repertoire effect через X/E/P; source не
меняется, новая edition не переключает active use, unregister не удаляет source
или history. См. REGISTRATION.md. Runtime standalone live host capability не
выводится из synthetic tests или metadata; owning X/G/E basis проверяется до
material operation. Original CLI retained только в development как
compatibility evidence, вне product payload; не grant.

Changed claim: named source/Method/plan/configuration delta сравнивать на claim
size; direct receiver owner даёт depends/mentions-only/unresolved. R хранит reach
и unsearched surfaces, L проверяет только affected use. No automatic latest,
universal event bus или graph authority service.

В обычной проектной работе не требовать, скачивать, копировать в проект или
полностью читать FPF-Spec, включая последовательное чтение частями/делегирование.
Локальная копия, hash в старой записи и DPF citation не разрешают это чтение.
Для primary FPF development/semantic audit нужны отдельные explicit Human
question/source/effect boundaries; использовать минимально достаточные loci.
Полный документ требует отдельного явного scope. Missing primary basis удерживает
только affected consequential claim/use, без выдуманной conformance и ослабления
Work/authority/evidence. Policy declared, не host enforcement.
