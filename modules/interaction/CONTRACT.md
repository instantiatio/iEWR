# I — bounded ordinary interaction и rehearsal

I.submit обращается только к C. I.present сохраняет material outcome/hold и
человеко-понятный target; renderer optional и имеет text-complete fallback.
Для этой описки internal IDs/hashes не foregrounded. Audit refs остаются в
точных input/owner records. Complete preferences, general Human response
interpretation и полнота F-02 discriminator не заявляются в B1.

Для actual bounded rehearsal явно выбрать synthetic request и current source
bindings как test inputs. Вызвать только необходимые owner APIs через I/C:
наблюдать current result/незавершённую попытку, получить bounded use assessment
и F result. На reuse — direct answer и stop. На hold — сообщить affected gap,
не повторять действие. На direct — отдельно вызвать X для точного разрешённого
action; его actual result/effect получить как evidence соответствующего use.
Материальную неопределённость не скрывать и не переводить в success.

Это instructions для отдельно выбранного test context, а не автоматическая
замена active AGENTS. Host `invoke.py` принимает ровно одно JSON message за
process; следующий message формирует действующий агент по наблюдению/запросу.
No autonomous loop. Не требуется повторно спрашивать Human о каждом technical
step внутри уже разрешённого synthetic B1 scope. После достаточного результата
stop, без B2 и без activation.
