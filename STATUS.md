# iEWR 7.0.8 Eternal Alpha status

Public research edition. The exact immediate basis is the preserved 7.0.7 candidate. The comparative trials used the supplied 7.0.6 release. See [PACKAGE.json](PACKAGE.json) and [release changes](RELEASE_NOTES.md).

| Evidence | Result and scope |
|---|---|
| Source priority | Comparison with both prior editions found the same source priority and reuse conditions. An F.19 reading checked the clarified instruction for constructing and checking a missing method. The original FPF, its index, task navigation and the MethodPack pair are byte-identical to 7.0.6. |
| Method choice in unfamiliar work | In a paired exhibit-timing task, both editions rejected the same-clock calculation for a separately clocked input, obtained the same three decisions and identified the unresolved case. The candidate also ran three boundary checks against the decision rule. Both finished without asking Human. This pair did not establish a more accurate primary result. |
| Ordinary project log | In a project with three archive checks, the agent created and appended compact FPF and MP entries without a request to log. The entries record a completed check, a failed digest comparison and a check held when a required sidecar was absent. The available evidence records actual operations and results. It does not isolate the contribution of each method from the task instruction. |
| Continuation with changed inputs | Another participant recovered the three archive checks using project files. It reused an unchanged inventory, reconsidered a replaced ZIP with the same name and completed the check held for the missing sidecar. The staging ZIP had no recorded prior fingerprint, so its inventory was checked again. In a second project, new calibration changed only one exhibit-timing result. The participant recalculated that case, retained two applicable results and appended the revised applications. |
| Input identity refinement | In the behavior-tested wording, the first participant recorded the staging ZIP fingerprint and the pending external comparison. A fresh participant used that fingerprint to retain the prior inventory and completed the comparison when the sidecar arrived. |
| Expanded record on request | The participant added a linked detailed explanation of the ZIP revision. Compact entries, original reports and inputs were preserved. |
| Recording cost | For three matched evidence sets, a single agent took about 4.8–5.4 s per compact entry and 7.7–12.9 s per expanded entry, excluding shared evidence recovery. These are drafting and appending measurements after the work. End-to-end time and causal savings were not established. |
| Question timing and handoff | In two fresh chats on the final instruction text, the agent recorded a short local check before requesting the external reference. In the longer case, it requested the reference before running the approximately 45-second local check and continued work. Both final handoffs used a four-word status and specified the needed input. The long check produced a complete log, and the SHA-256 was confirmed independently after a shell wrapper error. |
| Index generation and attachments | The carried-forward generator checks covered ordinary generation, a symlink at the former temporary path, a write failure, and overlapping runs. Attachment trials preserved and reopened two different originals with the same name and handled an unavailable original. |
| Clean package | Verified actual ZIP paths and bytes against the inventory and file map. The extracted original FPF index and MethodPack passed their supplied checks. The package has no project history and starts through README and AGENTS.md. |

The paired exhibit runs and the first archive operator used the initial cue. The continuation trials used the longer revised cue. A fresh chat on the previous package read the current four-sentence cue and checked the clock configuration before adapting the calculation. The latest edits connect method choice to each applicable step, clarify when to ask Human, and name the action to take when the method still has a gap. An F.19 reading of these edits and their neighbors checked who acts, when to act, and what to do. The log format and the guidance on retaining input identity are unchanged from the input identity trial. Parallel log work uses a designated writer; no automated locking is supplied.
